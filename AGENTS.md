# ClearSugar Community — Developer Notes

## Next.js version warning

This project uses Next.js 16 (App Router). APIs, conventions, and file structure may differ
from what you expect from older Next.js versions. Read the relevant guide in
`node_modules/next/dist/docs/` before writing code. Heed deprecation notices.

## Configuration contracts

These contracts are the single source of truth for how configuration, auth, and the
patient profile are wired. All code must conform.

### Environment variables (`.env`)

Required:
- `NIGHTSCOUT_URL` — base URL of the user's Nightscout instance (e.g. `http://localhost:1337`)
- `NIGHTSCOUT_API_SECRET` — Nightscout API secret
- `AUTH_SECRET` — NextAuth session secret (random, generated by setup)
- `CLEARSUGAR_API_KEY` — machine-client API key for timers/cron and companion apps (random, generated by setup)
- `CLEARSUGAR_DATA_DIR` — data directory (default: `./.data` in dev, `/opt/clearsugar/data` in prod)

AI insights (optional):
- `LLM_PROVIDER` — one of `anthropic` | `claude-cli` | `codex-cli` | `ollama` | `openai-compatible` | `none` (default `none`)
- `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL` (default `claude-sonnet-5`)
- `OLLAMA_URL` (default `http://localhost:11434`), `OLLAMA_MODEL`
- `OPENAI_COMPAT_URL`, `OPENAI_COMPAT_API_KEY`, `OPENAI_COMPAT_MODEL`
- `CLAUDE_CLI_PATH` (default `claude`), `CODEX_CLI_PATH` (default `codex`)

Optional integrations:
- `CLEARSUGAR_PREDICT_URL`, `CLEARSUGAR_PREDICT_TOKEN` — ML prediction microservice (falls back to physiological model when unset)
- `TCONNECT_WEBHOOK_URL`, `TCONNECT_WEBHOOK_TOKEN` — tconnectsync "Sync now" webhook
- `MOBILE_JWT_SECRET` — iOS companion app JWT signing (generated by setup)
- `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_PRIVATE_KEY_B64`, `APNS_BUNDLE_ID`, `APNS_SANDBOX` — Apple push (iOS companion app only)
- `DEMO_MODE` — `true` serves deterministic synthetic CGM/pump data instead of Nightscout (for trying the app and for screenshots)

### Local data store (`CLEARSUGAR_DATA_DIR`, via `src/lib/local-store.ts`)

- `auth/users` — `{ "users": [ { "username": string, "passwordHash": string /* bcrypt */, "role": "owner"|"parent"|"child"|"viewer", "createdAt": string /* ISO */ } ] }`
- `profile/patient` — `{ "name": string, "ageYears": number|null, "cgm": string, "pump": string, "insulinNotes": string, "clinicalNotes": string }`
  - All UI copy and LLM prompts must read patient identity from this profile at runtime.
  - When absent, fall back to the neutral phrase "the patient" and app title "ClearSugar".

### Auth

- Web: NextAuth v5 Credentials provider — username/password checked against `auth/users` (bcryptjs). Fail closed.
- Machine clients (systemd timers, cron): `X-API-Key: $CLEARSUGAR_API_KEY`.
- Mobile: `POST /api/auth/mobile/token` exchanges username/password for a 7-day HS256 JWT signed with `MOBILE_JWT_SECRET`.

### Hard rules

- No Home Assistant integration. No hardcoded hostnames, LAN IPs, personal names, or domains anywhere (localhost defaults are fine).
- Known limitation: analysis/ML feature code currently assumes the `America/New_York` timezone in several places (it must stay consistent with the Python training pipeline). Making this profile-driven is a welcome contribution.
- All optional integrations must degrade gracefully when unconfigured.
- Never commit `.env*` or the data directory.
